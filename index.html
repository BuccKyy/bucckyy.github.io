Human-Reviewed ERP Receipt Posting

The problem

Posting OCR-extracted receipt payloads into SAP is a high-stakes irreversible write: low-confidence fields, unit mismatches, approval hierarchies, and network timeouts can corrupt ERP ledgers.

How it works

Upload → OCR draft → human review UI → SAP preflight (GET) → controlled POST to InventoryGenEntries → read-after-write verification. State is journaled before the write with correlation IDs and an environment gate blocking prod writes in test mode.

Result → 88/88 focused pytest checks passed and 5/5 SAP read-back field checks matched on the isolated test database.

OCR · human-in-the-loop · SAP ERP · state machine · 88 pytest suite

▸ How it was verified

Test Suite: 88 focused pytest cases covering OCR field validation, state machine transitions, environment write guards, and timeout reconciliation.

Read-After-Write: Post-commit GET verifies 5/5 SAP fields (DocEntry, CardCode, ItemCode, Quantity, Price) against the journaled intent.
