operating principles

  1. Deterministic core, LLM at the edges. Arithmetic, scoring, pricing, and state transitions run in Python. The model handles language and interpretation.
  2. Contracts before prompts. Strict JSON, Pydantic models, typed enums, explicit status fields, and validation before anything reaches a user.
  3. Human review before irreversible actions. Approval gates for sends, posts, exports, and ERP writes. Show the source next to the proposed result.
  4. Evidence-based release. pytest, Playwright, contract tests, read-after-write checks. A release is PASS, FAIL, BLOCKED, or NOT TESTABLE — never “looks fine.”
  5. Local-first verification. Isolated adapters and fixtures let workflows run without touching production. Deployment boundaries are documented, not assumed.

CS-03 · client work · ERP-adjacent

Human-Reviewed ERP Receipt Posting

problem

Posting OCR-extracted receipts into SAP is a high-risk write: low-confidence fields, unit mismatches, approval policy, and uncertain network outcomes.

system

Upload → OCR draft → human review → SAP preflight (GET) → controlled POST to InventoryGenEntries → read-back. Posting state is persisted before the write; correlation IDs support reconciliation after timeouts. A server gate blocks production DB writes; tests run against the test DB.

outcome → 88 focused tests passed and 5/5 SAP read-back field checks matched. The OCR confidence gate intentionally routes low-confidence fields to a human.

test-database evidence — not a production ERP rollout

OCR · human-in-the-loop · SAP · state machine · pytest
