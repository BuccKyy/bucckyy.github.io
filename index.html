CS-03 · Production Client System · ERP-Adjacent

Human-Reviewed ERP Receipt Posting

Problem

Posting OCR-extracted receipt payloads into SAP is a high-stakes irreversible write: low-confidence fields, unit mismatches, approval hierarchies, and network timeouts can corrupt ERP ledgers.

System Architecture

Upload → OCR draft → human review UI → SAP preflight (GET) → controlled POST to InventoryGenEntries → read-after-write verification. State is journaled before the write with correlation IDs and an environment gate blocking prod writes in test mode.

Outcome → 88/88 focused pytest checks passed and 5/5 SAP read-back field checks matched on the isolated test database.

OCR · human-in-the-loop · SAP ERP · state machine · 88 pytest suite

▸ Engineering Evidence & Verification

Test Suite: 88 focused pytest cases covering OCR field validation, state machine transitions, environment write guards, and timeout reconciliation.

Read-After-Write: Post-commit GET verifies 5/5 SAP fields (DocEntry, CardCode, ItemCode, Quantity, Price) against the journaled intent.

Operating Principles

  1. Deterministic core, LLM at the edges. Arithmetic, scoring, pricing, and state transitions run in Python. The model handles language and interpretation.
  2. Contracts before prompts. Strict JSON schemas, Pydantic models, typed enums, explicit status fields, and schema validation before anything reaches a user.
  3. Human review before irreversible actions. Explicit approval gates for sends, posts, exports, and ERP writes. Always show the source data next to the proposed output.
  4. Evidence-based release criteria. Comprehensive pytest, Playwright, contract tests, and read-after-write verification. A release is PASS, FAIL, BLOCKED, or NOT TESTABLE — never “looks fine.”
  5. Local-first verification. Isolated adapters and test fixtures allow workflows to run without touching production. Deployment boundaries are documented, not assumed.
