CS-03 · Production Client System · ERP-Adjacent

Human-Reviewed ERP Receipt Posting

problem

Posting OCR-extracted receipt payloads into SAP is a high-stakes irreversible write: low-confidence fields, currency/unit mismatches, approval hierarchies, and uncertain network timeouts.

system

Upload → OCR draft → human review interface → SAP preflight (GET) → controlled POST to InventoryGenEntries → read-after-write verification. Posting state is persisted prior to the write; correlation IDs enable deterministic reconciliation. A server-side environment gate blocks production DB writes during testing.

outcome → 88 focused tests passed and 5/5 SAP read-back field checks matched. OCR confidence gates automatically route uncertain fields to human operators.

Operating Principles

  1. Deterministic core, LLM at the edges. Arithmetic, scoring, pricing, and state transitions run in Python. The model handles language and interpretation.
  2. Contracts before prompts. Strict JSON schemas, Pydantic models, typed enums, explicit status fields, and schema validation before anything reaches a user.
  3. Human review before irreversible actions. Explicit approval gates for sends, posts, exports, and ERP writes. Always show the source data next to the proposed output.
  4. Evidence-based release criteria. Comprehensive pytest, Playwright, contract tests, and read-after-write verification. A release is PASS, FAIL, BLOCKED, or NOT TESTABLE — never “looks fine.”
  5. Local-first verification. Isolated adapters and test fixtures allow workflows to run without touching production. Deployment boundaries are documented, not assumed.
